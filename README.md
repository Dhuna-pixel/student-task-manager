# 🎓 Student Task Manager

A cloud-based student task management web application designed to help students centrally organize and track their academic assignments based on deadlines, priority, and completion status.

The application provides complete **CRUD (Create, Read, Update, Delete)** functionality through a RESTful API and stores task data in a cloud-hosted MongoDB Atlas database.

## 🌐 Live Demo

* **Frontend:** https://student-task-manager-lilac.vercel.app
* **Backend API:** https://student-task-backend-wmkv.onrender.com/api/tasks

## 🎯 Problem Statement

Students often manage multiple academic tasks with different deadlines, priorities, and completion states. When task information is not maintained in a centralized system, students may miss deadlines, spend time on lower-priority tasks, or lose track of completed work.

The Student Task Manager provides a centralized platform for managing academic tasks and tracking their current status.

## ✨ Features

* **Create Tasks:** Add tasks with a title, course code, due date, and priority.
* **View Tasks:** Retrieve and display all saved tasks from MongoDB Atlas.
* **Update Tasks:** Advance task status through Pending, In Progress, and Completed.
* **Delete Tasks:** Remove completed or obsolete tasks.
* **Priority Management:** Categorize tasks as Low, Medium, or High priority.
* **Deadline Tracking:** Display the due date for each task.
* **Responsive Interface:** Accessible through modern desktop and mobile web browsers.
* **Cloud Deployment:** Frontend, backend, and database are hosted using cloud services.

## 🔗 REST API

The backend provides RESTful API endpoints for task management.

| Operation | HTTP Method | Endpoint         | Description              |
| --------- | ----------- | ---------------- | ------------------------ |
| Create    | POST        | `/api/tasks`     | Creates a new task       |
| Read      | GET         | `/api/tasks`     | Retrieves all tasks      |
| Update    | PUT         | `/api/tasks/:id` | Updates an existing task |
| Delete    | DELETE      | `/api/tasks/:id` | Deletes an existing task |

### Example API Flow

```text
Frontend
   ↓
HTTPS Request
   ↓
Express REST API
   ↓
Mongoose
   ↓
MongoDB Atlas
   ↓
Response
   ↓
Frontend
```

## 🗄️ Database Design

The application uses a MongoDB collection for storing student tasks.

Each task contains the following fields:

| Field       | Type     | Description                                          |
| ----------- | -------- | ---------------------------------------------------- |
| `_id`       | ObjectId | Unique identifier automatically generated by MongoDB |
| `title`     | String   | Name/title of the academic task                      |
| `course`    | String   | Course code associated with the task                 |
| `dueDate`   | Date     | Deadline of the task                                 |
| `priority`  | String   | Low, Medium, or High                                 |
| `status`    | String   | Pending, In Progress, or Completed                   |
| `createdAt` | Date     | Automatically records creation time                  |
| `updatedAt` | Date     | Automatically records last update time               |

### Validation

* `title`, `course`, and `dueDate` are required.
* `priority` is restricted to `Low`, `Medium`, or `High`.
* `status` is restricted to `Pending`, `In Progress`, or `Completed`.
* `priority` defaults to `Medium`.
* `status` defaults to `Pending`.

## 🚀 Application Workflow

1. The student opens the web application through the browser.
2. The frontend is served through Vercel.
3. The student creates, views, updates, or deletes tasks.
4. The frontend communicates with the backend through HTTPS REST API requests.
5. The Express backend processes the requests.
6. Mongoose communicates with MongoDB Atlas.
7. The database operation result is returned to the backend.
8. The backend sends the response back to the frontend.
